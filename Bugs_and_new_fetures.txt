Project Summary:
  AI Command Center is a Chrome New Tab extension built with vanilla JavaScript
  and CSS. It provides an AI tool launcher, prompt library, multi-AI router,
  Gemini AI integration, workspaces, one-click stacks, and localhost quick access.
  Files: newtab.html, 11 JS modules, 4 CSS files, manifest.json.

================================================================================
  SECTION 1 — BUGS FOUND (Total: 18 Bugs)
================================================================================

--- CRITICAL BUGS ---

BUG 01: XSS Vulnerability — Workspace Notes Rendered Without Sanitization
  File   : js/workspaces.js  (line 62)
  Code   : ${ws.notes || 'No notes added yet.'}  — rendered directly in innerHTML
  Impact : A malicious workspace note like <img src=x onerror=alert(1)> would
           execute arbitrary JavaScript in the extension context.
  Fix    : Use escapeHtml(ws.notes) before injecting into innerHTML, exactly as
           prompts.js already does for prompt.content.

BUG 02: XSS Vulnerability — Tool Name/Description Not Escaped in Tools Grid
  File   : js/tools.js  (lines 144–147)
  Code   : ${tool.name} and ${tool.description} injected directly into innerHTML.
  Impact : A custom tool with name '<script>...</script>' or a crafted description
           can execute JavaScript. Custom tools are user-controlled.
  Fix    : Wrap tool.name and tool.description with an escapeHtml() call before
           injecting into the card HTML template.

BUG 03: XSS Vulnerability — Workspace Name/Description Not Escaped
  File   : js/workspaces.js  (lines 47–48)
  Code   : ${ws.name} and ${ws.description} inside innerHTML directly.
  Impact : Same as BUG 01 — user-supplied workspace fields rendered raw.
  Fix    : Apply escapeHtml() to ws.name and ws.description.

BUG 04: javascript: URL Not Blocked in Tool Launcher
  File   : js/tools.js  (lines 46–48)
  Code   : chrome.tabs.create({ url: tool.url }) — url is taken directly from storage
           with only a basic https?:// prefix check when adding the tool.
  Impact : A user could manually edit storage and inject 'javascript:alert(1)' as a
           tool URL. chrome.tabs.create with a javascript: URL is blocked by Chrome
           for extensions but window.open() in the fallback branch could execute it.
  Fix    : Validate URL against an allowlist of protocols (https:, http:) both at
           tool-add time AND at launch time before passing to window.open.

BUG 05: importBackup() Blindly Overwrites All Data Without Validation
  File   : js/storage.js  (lines 215–221)
  Code   : const parsed = JSON.parse(jsonString); await this.set(parsed);
  Impact : Any malformed or malicious JSON file passed to importBackup() will be
           written directly to chrome.storage.local without checking keys, data types,
           or required fields. Could corrupt all stored settings/tools/prompts.
  Fix    : Validate parsed object — check that keys are in the expected set
           (tools, stacks, prompts, workspaces, settings) and that arrays are arrays.
           Reject unknown or unexpected keys before writing.

--- MODERATE BUGS ---

BUG 06: Duplicate Step Numbers in app.js Initialization (Comment Bug + Logic Confusion)
  File   : js/app.js  (lines 18, 23, 26, 29)
  Code   : Step 4 is used twice ("Initialize Localhost..." and "Initialize Universal
           Search"). Step 5 is also used twice.
  Impact : Misleading comments make initialization order unclear and maintenance error-prone.
  Fix    : Renumber steps sequentially: 1–10, correctly reflecting each module's
           order of initialization.

BUG 07: localhostTabs Not Included in initDefaults() Storage Fetch
  File   : js/storage.js  (line 72)
  Code   : const data = await this.get(['tools', 'stacks', 'prompts', 'workspaces',
           'settings', 'recentTools']);  — 'localhostTabs' is missing.
  Impact : Even though localhostTabs seeding code exists below (lines 186–193),
           it is always triggered because data.localhostTabs is always undefined
           in this call — even when the user already has saved localhost tabs.
           This overwrites user's saved localhost tabs every time the extension loads.
  Fix    : Add 'localhostTabs' to the get() array on line 72 so it is read before
           the conditional seed check.

BUG 08: Gemini Model Silently Overwritten on Fallback Without Saving to Storage
  File   : js/gemini.js  (lines 358, 424)
  Code   : this.model = 'gemini-2.0-flash'; — set in-memory only; not persisted.
  Impact : If the user has selected a non-default model (e.g., gemini-1.5-pro-latest)
           and a fallback occurs, the in-memory model changes to gemini-2.0-flash
           but the settings view still shows the old model. Next reload restores the
           broken model, causing repeated silent fallbacks every session.
  Fix    : After updating this.model in the fallback, call saveConfig() or update
           the relevant storage key so the preference is persisted correctly.

BUG 09: Unbounded chatHistory Growth in AssistantManager
  File   : js/assistant.js  (lines 175, 234)
  Code   : this.chatHistory.push(...)  — no maximum size enforcement.
  Impact : Long chat sessions accumulate every message pair. When passed to
           GeminiClient.generateChat(this.chatHistory), the context window grows
           indefinitely — eventually exceeding Gemini's token limit and causing
           API failures, or causing out-of-memory issues in long sessions.
  Fix    : Cap chatHistory at a sensible limit (e.g., last 30–50 messages) by
           trimming older entries: this.chatHistory = this.chatHistory.slice(-50).

BUG 10: chrome.storage.local Callbacks Missing runtime.lastError Checks
  File   : js/storage.js  (lines 16, 43, 60)
  Code   : chrome.storage.local.get(keys, (result) => resolve(result)) — no
           chrome.runtime.lastError check inside the callback.
  Impact : If storage operations fail (quota exceeded, corrupt state, etc.) the
           error is silently swallowed and resolve() is called with potentially
           undefined or empty result — leading to hard-to-debug data-loss bugs.
  Fix    : Check chrome.runtime.lastError inside every callback:
           if (chrome.runtime.lastError) { reject(chrome.runtime.lastError); return; }

BUG 11: Keyboard Shortcut Handler Does Not Check contenteditable Elements
  File   : js/app.js  (lines 54–57)
  Code   : Checks activeElement.tagName for 'input', 'textarea', 'select' only.
  Impact : If a user is typing inside a contenteditable div (e.g., rich text
           fields, or browser-injected controls), Alt+C / Alt+G / Alt+P will still
           fire and open tabs unexpectedly.
  Fix    : Add check: || document.activeElement.isContentEditable
           to the guard condition before firing shortcuts.

BUG 12: Search '/' Shortcut Does Not Check contenteditable Areas
  File   : js/search.js  (lines around 109–115)
  Code   : !document.activeElement.matches('input, textarea') — missing check for
           contenteditable.
  Impact : Pressing '/' in a contenteditable area will steal focus to the search bar.
  Fix    : Also exclude contenteditable elements:
           || document.activeElement.isContentEditable.

BUG 13: Prompt Title Rendered Without Sanitization in Cards
  File   : js/prompts.js  (line 99)
  Code   : ${prompt.title} — injected directly into innerHTML without escapeHtml().
  Impact : Prompt titles are user-controlled. A crafted title could inject HTML.
           prompt.content IS escaped (line 114), but title is not.
  Fix    : Apply escapeHtml(prompt.title) before injecting into the card template.

--- MINOR BUGS ---

BUG 14: SearchManager.init() is Called Async but Not Awaited
  File   : js/app.js  (line 26)
  Code   : SearchManager.init();  — not awaited.
  Impact : SearchManager.init() is actually async (it awaits StorageManager.get).
           Not awaiting means engine state (activeEngine, customEngines) may not
           be fully loaded before the user starts interacting with the search bar.
  Fix    : Change to: await SearchManager.init();

BUG 15: escapeHtml() is Defined in Multiple Files Without Sharing
  Files  : js/assistant.js  (line 357), js/localhost.js, js/prompts.js  (line 276)
  Code   : Each module defines its own escapeHtml() implementation inline.
  Impact : No bug in isolation, but the duplication means if one implementation
           has a flaw it is not fixed everywhere; easy to forget escaping in
           tools.js and workspaces.js which do NOT define it at all.
  Fix    : Define a single shared escapeHtml() utility (in ui.js or a utils.js)
           and reference it consistently from all modules.

BUG 16: Default Stack toolIds Reference Tools That May Not Exist
  File   : js/storage.js  (lines 85–115)
  Code   : toolIds: ['chatgpt', 'claude', 'cursor', 'kaggle', 'google-colab', ...]
  Impact : If a user resets or selectively deletes tools, default stacks still
           reference deleted tool IDs. In renderStacks(), the missing tool falls
           back to { name: tId, iconBg: '#6366f1', iconText: 'AI' } but still
           passes tId directly into launchTool() — which silently does nothing
           if the tool is not found, with no user feedback.
  Fix    : In launchStack(), check if tool is found and show a warning toast for
           any tool in the stack that could not be resolved.

BUG 17: Workspace Deletion Guard Uses Hardcoded 'ws-main' ID
  File   : js/workspaces.js  (line 51)
  Code   : ${ws.id !== 'ws-main' ? ... : ''} — delete button hidden only for ws-main.
  Impact : If user renames ws-main or the default workspace id changes, the
           hardcoded guard breaks. Not a crash bug, but a fragile design.
  Fix    : Add an isDefault: true flag to the default workspace data and check
           that flag instead of hardcoding the ID string.

BUG 18: Multi-AI Challenge Copies Prompt to Clipboard But Does Not Actually Send to AI
  File   : js/assistant.js  (lines 300–345)
  Code   : The Multi-AI Challenge only copies the prompt to clipboard and opens
           each selected AI's website URL in a tab. It does NOT send the prompt
           to any AI via API — the name "Challenge" implies comparison, but
           there is no actual response capture or side-by-side rendering.
  Impact : The feature is misleading in its name and the UI badge says "NEW" —
           users will expect actual output comparison but get manual copy-paste flows.
  Fix    : Either rename the feature to "Multi-AI Launcher" to accurately reflect
           its behavior, or implement actual side-by-side Gemini-powered comparison
           (see New Features section below).


================================================================================
  SECTION 2 — WHAT TO DO FOR RELIABILITY
================================================================================

RELIABILITY 01: Add a Global Error Boundary / Init Failure Handler
  Currently: If any module.init() throws, the DOMContentLoaded catch block in
  app.js logs to console and silently leaves the extension in a broken state.
  Action: Display a visible error panel to the user with a "Reset Extension" button
  that calls StorageManager.set with default values and reloads the page, so the
  user is never stuck on a blank/broken new tab.

RELIABILITY 02: Guard All StorageManager Calls Against Quota Errors
  Action: Wrap chrome.storage.local.set() in a try-catch that detects
  QUOTA_BYTES_PER_ITEM exceeded or QUOTA_BYTES exceeded errors, alerts the user,
  and optionally triggers a partial backup export automatically.

RELIABILITY 03: Add chrome.runtime.lastError Checks to All Storage Callbacks
  Action: As noted in BUG 10 — every chrome.storage callback must check for
  lastError before resolving the promise. This prevents silent data-loss bugs.

RELIABILITY 04: Validate All User Inputs Before Storage Write
  Currently: Custom tool URL, name, search engine URL, and workspace names are
  stored after only minimal checks. The importBackup() function has no validation.
  Action: Create a dedicated validate() function for each data type (Tool, Stack,
  Prompt, Workspace, SearchEngine) with type checks, length limits, and required
  field checks. Call validate() before every StorageManager.set().

RELIABILITY 05: Add Offline Detection and Graceful Fallback for Gemini Calls
  Currently: If the user's internet drops mid-conversation, Gemini API calls fail
  with a generic network error and the assistant shows nothing.
  Action: Wrap all generateText/generateChat calls in a check for navigator.onLine.
  If offline, show a friendly "You appear to be offline" message and offer the
  offline rule-based router as a fallback for the Smart Router.

RELIABILITY 06: Add Retry Logic for Transient Gemini API Failures
  Currently: Any 500 or 503 from Gemini throws immediately with no retry.
  Action: Implement a simple exponential backoff retry (max 2 retries) for
  5xx status codes in generateText() and generateChat().

RELIABILITY 07: Sanitize and Persist Gemini Model After Fallback
  Action: As noted in BUG 08 — when a model fallback occurs, call saveConfig()
  to persist the new model so the user's selection is consistent across reloads.

RELIABILITY 08: Add Input Length Limits to All Free-Text Fields
  Currently: Tool description, workspace notes, prompt content, and chat input
  have no character limits — extremely long values could crash the UI or exceed
  storage limits.
  Action: Add maxlength attributes to all textarea/input fields in newtab.html,
  and validate length in JS before storage writes (e.g., notes <= 5000 chars,
  prompt content <= 10000 chars).

RELIABILITY 09: Debounce Search Input Live Filter
  Currently: handleLiveFilter() is triggered on every keypress without debounce.
  For large tool lists (100+ tools) this causes repeated re-renders on every character.
  Action: Wrap handleLiveFilter with a debounce (150ms delay) to avoid
  unnecessary re-renders during fast typing.

RELIABILITY 10: Cap chatHistory to Prevent Token Overflow
  Action: As noted in BUG 09 — limit chatHistory to the last 40–50 messages.
  Display a "Chat history trimmed to last 50 messages" notice if the cap is reached.


================================================================================
  SECTION 3 — WHAT NEEDS TO BE IMPROVED
================================================================================

IMPROVE 01: Move escapeHtml() to a Shared Utility Module
  Currently defined in 3 separate files; missing in tools.js and workspaces.js.
  Create a utils.js or add to ui.js and reference from all modules.

IMPROVE 02: Rename Misleading Feature Names
  "Multi-AI Challenge" implies live side-by-side AI comparison but only copies
  a prompt and opens tabs. Rename to "Multi-AI Launcher" or implement true
  comparison (see New Features).

IMPROVE 03: Decouple Module Interdependencies
  SmartRouter references ToolsManager.toolsList directly, AssistantManager calls
  GeminiClient directly. If load order changes, these will fail silently.
  Use event-based initialization (CustomEvent / dispatchEvent) or dependency
  injection to decouple modules.

IMPROVE 04: Add Edit Capability to All Entities
  Currently, users can CREATE and DELETE tools, stacks, prompts, and workspaces
  but CANNOT EDIT them. To change a tool's URL or a workspace's description,
  they must delete and recreate it.
  Action: Add an "Edit" modal for each entity type (Tool, Stack, Prompt, Workspace).

IMPROVE 05: Replace confirm() Dialogs With Custom Modal Confirmations
  Currently: deleteCustomTool(), deleteStack(), deleteWorkspace() all use the
  browser's native confirm() dialog.
  Issue: Chrome blocks confirm() in some extension contexts and it is jarring UX.
  Action: Replace with a small themed confirmation modal matching the extension's
  glassmorphic design.

IMPROVE 06: Add Persistent Settings for Gemini Persona and Temperature
  Currently, persona and temperature are reset on each API call. Users cannot
  fine-tune per-session behavior from the UI.
  Action: Add sliders/selects in the Settings or Gemini Engine view to control
  temperature (0.1–1.0) and maximum output tokens per call, saved to storage.

IMPROVE 07: Add Empty State Messaging and Onboarding for First-Time Users
  When the extension loads for the first time, users land on the Dashboard with
  30+ tools but no guidance. There is no onboarding flow, walkthrough, or tooltip.
  Action: Add a first-run welcome modal that explains the 5 key features and
  prompts the user to add their Gemini API key.

IMPROVE 08: Improve CSS Variables Coverage for Full Theme Consistency
  Some inline styles in JS-generated HTML (e.g., workspaces.js, router.js)
  use hardcoded hex colors (#6366f1) instead of CSS variables (--accent-primary).
  This means accent color changes in settings do not propagate everywhere.
  Action: Audit all JS-generated HTML and replace hardcoded color values with
  the corresponding CSS variable references.

IMPROVE 09: Add Timestamps and Last Used to Recent Tools
  The recentTools list stores timestamps but they are never displayed to the user.
  Action: Show relative time ("2h ago", "Yesterday") below each chip in the
  recently used row for better context.

IMPROVE 10: Improve Manifest with Content Security Policy Declaration
  The manifest.json does not declare a content_security_policy.
  Chrome MV3 applies default CSP restrictions, but declaring it explicitly
  communicates intent and prevents accidental policy relaxation.
  Action: Add an explicit content_security_policy key to manifest.json.

IMPROVE 11: Add Drag-to-Reorder for Tools, Stacks, and Prompts
  Currently, tools, stacks, and prompts appear in add order with no way to
  re-sort them. Users who want their most-used tools at the top must delete and
  re-add everything.
  Action: Implement HTML5 drag-and-drop reordering with persistence via
  StorageManager.set on drop.

IMPROVE 12: Make Category Pills Count Badges More Accurate
  The count shown on category pills includes ALL tools. When filtering by a
  category, the count correctly filters — but the "all" pill always shows the
  total even during filtered search, which can confuse users.
  Action: Update pill counts to reflect current visible tools count when a
  search filter is active.

IMPROVE 13: Add Tool URL "Open to Test" Button in Add Tool Modal
  When adding a custom tool, users cannot preview whether the URL is correct
  without saving it first.
  Action: Add a small "Test URL" button in the Add Tool modal that opens the
  entered URL in a new tab before saving.

IMPROVE 14: LocalhostManager Lacks HTTPS Support for Secure Dev Servers
  The parseInput() function defaults to http:// protocol.
  Some local dev servers run on HTTPS (e.g., Vite with --https, mkcert).
  Action: Add a toggle in the Add Localhost modal to select http:// or https://
  and store the protocol preference per entry.

  SECTION 4 — NEW FEATURES TO ADD
================================================================================

FEATURE 01: True Multi-AI Comparison Mode (Side-by-Side Output)
  Description: Send the same prompt to multiple AI models (Gemini variants or
  external APIs) simultaneously and display results side-by-side in a split-pane
  view inside the extension. Include a "Best Answer" voting/rating mechanism.
  Modules to modify: assistant.js, newtab.html (new layout panel), gemini.js.

FEATURE 02: Prompt Version History & Undo
  Description: Every time a prompt is edited or Gemini-enhanced, save the
  previous version. Add a "History" icon on each prompt card showing a timeline
  of past versions that can be restored with one click.
  Storage key: promptHistory: { [promptId]: [versions array] }

FEATURE 03: AI Workflow Builder — Drag-and-Drop Pipeline Editor
  Description: A visual canvas where users drag AI tool blocks and connect them
  with arrows to define multi-step pipelines (e.g., Perplexity → Claude → Cursor).
  Each block can have a custom prompt template. Pipelines are saved as Workflows
  and appear in the Stacks section.

FEATURE 04: Browser History Search Integration
  Description: Use chrome.history API (requires "history" permission) to allow
  users to search their browser history directly from the search bar — alongside
  AI tool filtering. Add "From History" result chips below the search input.

FEATURE 05: Daily Focus Mode / Productivity Timer
  Description: Add a Pomodoro-style timer widget to the header area (next to the
  clock). Users can set a task goal, pick a time block (25/45/60 min), and the
  timer quietly pulses in the header. On completion, a toast notification fires.

FEATURE 06: Pinned Notes / Scratch Pad Widget on Dashboard
  Description: A small sticky-note panel on the Dashboard for quick thoughts,
  to-do lists, and clipboard snippets. Supports markdown preview. Persisted to
  storage. Can be pinned as a floating panel or collapsed to a corner icon.

FEATURE 07: Tool Usage Analytics Dashboard
  Description: Track how often each tool is launched over time and show a simple
  weekly heatmap and "Top 5 Tools This Week" summary card on the Dashboard.
  Store timestamped launch events in chrome.storage.local with a rolling 90-day window.

FEATURE 08: OpenAI / Anthropic API Integration Alongside Gemini
  Description: Extend the Gemini AI Engine tab to support additional providers —
  OpenAI (GPT-4o) and Anthropic Claude API — so users can run the same prompts
  against different providers and compare. Each provider has its own API key input.

FEATURE 09: Custom Category Creator
  Description: Currently, tool categories are hardcoded in data/categories.js.
  Add a "Manage Categories" section in Settings where users can create, rename,
  recolor, and delete custom categories. Tools can be reassigned to new categories.

FEATURE 10: Prompt Sharing via URL / Export Link
  Description: Allow users to generate a shareable URL that encodes a single
  prompt template (base64). Visiting the link auto-imports the prompt into the
  recipient's AI Command Center. Useful for team prompt sharing.

FEATURE 11: Tab Group Integration (Chrome Tab Groups API)
  Description: When launching a Stack or Workspace, automatically group all
  opened tabs into a named Chrome Tab Group (using chrome.tabs.group and
  chrome.tabGroups API). Requires adding "tabGroups" to manifest permissions.

FEATURE 12: Gemini Streaming Chat (Token-by-Token Response)
  Description: Currently, Gemini responses appear all at once after the API call
  completes. Implement streaming using the Gemini streaming endpoint
  (:streamGenerateContent) and render tokens to the chat bubble progressively
  for a live "typing" feel.
  File to modify: gemini.js — add generateChatStream() method.

FEATURE 13: Global Hotkey Customizer
  Description: The current Alt+C / Alt+G / Alt+P shortcuts are hardcoded.
  Add a Hotkey section in Settings where users can assign any keyboard shortcut
  to any tool in their library. Saved to storage and applied at runtime.

FEATURE 14: Cloud Sync via Google Drive (Optional)
  Description: Add an optional "Cloud Sync" toggle in Settings that uses the
  chrome.identity API to authenticate with Google and sync the user's extension
  data (tools, prompts, stacks, workspaces) to a Google Drive JSON file.
  This allows the same configuration across multiple devices / Chrome profiles.

FEATURE 15: AI-Powered Tool Discovery
  Description: A "Discover New Tools" section powered by Gemini — user describes
  a task they cannot find a good tool for, and Gemini recommends new AI tools
  (not yet in the library) with links. The user can add recommended tools with
  one click.

FEATURE 16: Dark/Light Mode Scheduled Auto-Switch
  Description: Allow users to schedule automatic theme switching based on time
  (e.g., Light mode 8am–6pm, Dark mode 6pm–8am) using the system clock in ui.js.
  Preference saved as scheduleTheme: { enabled, lightFrom, darkFrom } in settings.
